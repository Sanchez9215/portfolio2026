# XOPS Component Registry

Registry of already-built components in `design-systems/xops/`. Always check before building.

| design-system name | file | states covered |
| ------------------- | ---- | ---- |
| button | `design-systems/xops/components/Button.tsx` | default, hover, active/pressed, focus, disabled — full checklist complete. No `selected` state — none of the 4 Figma variants show one; N/A for Button. Third variant `text` added for clickable cell values (e.g. Table): neutral `text.primary` label, no border/background at rest, background-only hover/active (`state.hover-on-surface`/`state.active-on-surface`, matches `secondary`) — no color shift, no underline |
| icon | `design-systems/xops/components/Icon.tsx` | Shared low-level primitive — renders any `public/xops/icons/*.svg` as a CSS-masked span so its color is token-driven (`color` prop) instead of baked into the SVG file. Used by Sidebar and GlobalHeader; any future component needing an icon should use this rather than an `<img>` |
| sidebar (nav) | `design-systems/xops/components/Sidebar.tsx` | default, hover, focus, active (top-level text color + submenu row bg/border/text). Submenu only implemented for the "Software" item (Overview/All Software) per audited Figma nodes 471:10219; other top-level items have no submenu in the source design. `activeItem`/`activeSoftwareItem` props control state — no internal routing logic yet. Icons render via `Icon`, recolored to `text-secondary` (grey.700) |
| global header | `design-systems/xops/components/GlobalHeader.tsx` | static presentational — search input (placeholder only, no real search wired), notification badge (count via prop), avatar (decorative color-fill circle, no photo asset provided) + online-status dot. Audited from Figma node 471:10330. Icons render via `Icon`; `left_panel_close`/`notifications` recolored to `text-secondary` (grey.700), `search` at `text-disabled` (grey.500, matches its original asset color). Icon buttons have full hover/active/focus states (radius.6, reusing existing surface tokens) |
| count | `design-systems/xops/components/Count.tsx` | Standalone — plain colored number (heading-24 weight, grey.600), no background/pill. Split out of `PageHeader` per user direction since it's a distinct reusable unit, not a `PageHeader`-only detail |
| page header | `design-systems/xops/components/PageHeader.tsx` | title (required) + optional `Count` (divider only appears when count is present) + fixed right-side meta (icon + timestamp text via props, not a generic slot — per user direction, this shape is reused ~90% of the time as-is; a separate future component will handle h3-level sub-section metadata). Audited from Figma node 471:10988 |
| grid | `design-systems/xops/components/Grid.tsx` | Layout primitive, not Figma-audited — built directly from the confirmed `Grid` token tier (`columns`, `gutter.default`/`gutter.tight`, `margin`). `Grid` sets up the 12-col CSS Grid track; `GridItem` takes a `colSpan` (1–12) prop for width. `gutter` prop toggles `default`/`tight`. **No longer applies its own horizontal margin** (`padding-inline` removed) — margin is now owned by whatever container places `Grid` (e.g. the Overview page's `main`), so a page's full-width chrome (like `PageHeader`) and its `Grid`-based content always share exactly one margin source instead of two stacking. Consequence: any Storybook story rendering `Grid` standalone (no page shell supplying its own padding) now shows edge-to-edge instead of margined — see Deferred. No responsive breakpoints yet (single fixed-width, per `progress.md`). `GridItem` now forwards a ref (for measuring rendered card height). |
| table | `design-systems/xops/components/Table.tsx` | Data-driven — takes a `columns: Column<T>[]` config + `data: T[]`, no hardcoded rows; a column's `render(row)` can return arbitrary content (e.g. `LogoTile` + name for a "logo+text" cell, first used in Top Non-Compliant Software's Software column against `public/xops/publisher-logos/`). Semantic `<table>`/`<thead>`/`<tbody>` (deliberately not Figma's div-flex reference — real markup for accessibility: `scope="col"`, `aria-sort`). `Column.width`: `fixed`(px, e.g. logo/badge) / `auto`(content-hugging, never grows) / `flex`(grows to fill remaining space, e.g. name columns). Row height intrinsic (no height token — `padding + content`). Header: `surface.table-header` bg (grey.50), `text.secondary` (grey.700) label at `font-weight-medium`. Row hover: `surface.table-row-hover` (grey.50, its own token — decoupled from Button's `state.hover-on-surface` so the two can diverge). Sortable columns render a click target with the `Arrows` icon (active column → `text.primary`, inactive → `text.secondary`). Every column carries `spacing.12` padding on all sides by default; the first column's left padding grows to `spacing.24` (reserved for a future drag-handle, see Deferred: column drag-to-reorder) **only when `chrome={true}`** (standalone, customizable tables) — tied to the `chrome` prop rather than a separate flag, since drag-to-reorder/column-visibility only apply to full standalone tables, not tables embedded in a `Card` with a fixed column set. Wrapper radius is top-only: `radius.12` when `chrome={true}` (flush/square bottom so `Pagination` attaches directly underneath), `radius.6` when `chrome={false}` (matches `Stat`/`Card`'s radius for visual consistency when embedded) — both clip via `overflow: hidden` on the outer wrapper. `chrome` prop: `true` (default) renders full outer chrome for standalone/full-page use; `false` renders bare markup (top corners only) so `Table` can sit inside `Card` without doubling the border/radius. Dual-edge scroll-fade affordance (`brand.50` → transparent, 164px, audited from Figma 471:11450) fades in/out via `scrollLeft`/`scrollWidth` + `ResizeObserver`, signaling hidden overflowed columns on either side — color is a visual approximation of the Figma asset, not pixel-sampled exact. Structure audited from Figma 471:11024 — content/columns/exact styling explicitly not final. States still open: selection checkbox column, empty state, loading state, plus badge/icon+text/avatar+text cell content variants. Header row is `position: sticky`. `.outer`/`.scroll` can grow to fill a taller sibling card or shrink+scroll vertically when a parent constrains height. `"fixed"`-width columns truncate with ellipsis; `"auto"`-width columns force `nowrap` via `data-width` (previously broken — relied on `<col>` `white-space`, which browsers ignore) |
| card | `design-systems/xops/components/Card.tsx` | Single variant/size — title (`subheading-16` medium, `text.primary`, resolved from Figma's raw `#000` rather than a new one-off) + generic content slot. Border-only chrome (`border.divider`, `radius.6` — same 4px→6px rounding precedent as `Pagination`'s pills and `LogoTile`). No header trailing-action slot (audited Figma showed one card with an `opacity-0` chevron, confirmed dead/unintentional). Height is not a token — fills its grid cell (`height: 100%`) and relies on CSS Grid's default `align-items: stretch` to equalize height across a row automatically; width/gap controlled entirely by `Grid`/`GridItem`, not by `Card` itself. `.content`'s flex-basis fixed from `0` to `auto` — the `0` value caused `Grid`'s `grid-auto-rows: auto` measurement pass to treat Card's content as collapsible-to-zero, undersizing the row and clipping real content once actual cards (not placeholder text) were rendered on a real page. `Table` (with `chrome={false}`) is the confirmed pattern for embedding a table inside a card — `Table` never gets wrapped when standalone. Researched via `/design-system-analysis` (Carbon Tile + Ant Card) |
| menu | `design-systems/xops/components/Menu.tsx` | `Menu`/`MenuOption` — floating panel of selectable rows (hover via `state.hover-on-surface`; selected matches Sidebar's active-submenu treatment exactly — `nav.background-active` + `brand.primary` text), extracted as its own primitive because more than one consumer needs the shape (Dropdown now, column-visibility toolbar soon). **Not Figma-audited** — no open-menu-state reference existed in any pulled node; panel/hover styling is still token reuse, unconfirmed against a design source (selected state now grounded in an established pattern) |
| dropdown | `design-systems/xops/components/Dropdown.tsx` | Trigger (selected label + `keyboard_arrow_down`, rotates open) composing `Menu` for the panel. `size` prop off the shared control-height scale (small/medium/large). Click-outside and Escape close it. Structure audited from Figma 471:11024 (pagination's items-per-page control) — but that audit only showed the closed trigger, not the open panel (see `menu` row above) |
| pagination | `design-systems/xops/components/Pagination.tsx` | Items-per-page `Dropdown`, row-range text ("1-20 of 3,267"), editable jump-to-page `<input>` (clamped 1–totalPages, commits on blur/Enter), prev/next `Button iconOnly` nav (`chevron_backward`/`chevron_right`, disabled at range ends). Bar background: `surface.pagination-bar` (grey.300 @ 25% opacity) + `blur(8px)` — deliberate glass treatment, only floating-surface component so far that isn't a solid token. Bottom radius matches `Table`'s top radius (`radius.12`) for flush attachment. Audited from Figma 471:11024. **Not yet wired**: meant to sit pinned/overlapping the bottom of `Table`'s scroll area (rows scroll behind the blur) — currently just stacks below in normal flow; real positioning deferred to screen assembly |
| logo tile | `design-systems/xops/components/LogoTile.tsx` | Bounded image container — `bg.white`, `border.divider`, `radius.6`, `object-cover` fill. `size` prop: `small`(24)/`medium`(32)/`large`(60), its own `logoTileSize` primitive tier (deliberately not the shared `control-height` scale — a 60px step doesn't belong on an interactive-control scale). One component confirmed across two audited contexts at different sizes: table cell (Figma 554:1665, 32px) and Profile-header (Figma 471:11505, 60px) — same company logo, same container shape, just scaled. A third instance is expected in the profile "zoom" surface |
| tag | `design-systems/xops/components/Tag.tsx` | Single size — body-14, no vertical padding (height is intrinsic to the font's line-height, not a token), `spacing.12` horizontal padding, `radius.full`. `status`: `success`/`warning`/`danger`/`neutral`. Tint+text only, no `solid` variant built. `text` step is `.800` on all four ramps (not `.900` or `.700` — `.700` failed WCAG AA for warning/danger against their own tint background; `.800` passes all four). No leading-icon slot (only icon-size token is 20px, would overflow the tag's own ~20px height) and no removable/dismissible variant (display-only, matches the actual table status-pill use case). Researched via `/design-system-analysis` against Carbon, Ant, and Primer's Tag/Label/Token components |
| stat | `design-systems/xops/components/Stat.tsx` | Chrome-optional content primitive — label (body-14 medium, `text.secondary`) + value (24px regular, size/line-height from `heading-24`, `text.primary`) + optional `meta` (body-14 regular, `text.secondary`, e.g. a percentage). Optional `style` prop for per-instance overrides (flagged as a possible future size variant). Filled-only (no plain/borderless variant — standardized across all reference instances in Figma, including License Utilization's Total Owned/Assigned pair, which was plain in the source design but unified to filled here). Background `surface.stat` (semantic token, grey.50 — revised down from an initial grey.100), `radius.6`, `spacing.16` padding all around, `spacing.8` gap both label→value and value→meta. `flex: 1 0 0%` + `min-width: 0` by default, so any row of `Stat`s (e.g. License Utilization's Total Owned/Assigned pair) splits the row evenly instead of hugging content width — matches Figma's own `flex-[1_0_0]` on the reference tiles. Deliberately kept separate from `Card` rather than folding chrome/background variants into it — `Card` is a generic arbitrary-content container, `Stat` has a fixed internal shape (label/value/meta), and `Stat` tiles are frequently placed inside a `Card` (e.g. Infrastructure Data Health's Summary Card), which would create contradictory nested-chrome requirements if `Stat` were just a `Card` variant |
| legend | `design-systems/xops/components/Legend.tsx` | Stack of rows, each: color swatch (`legendSwatchSize` primitive, 12px, `radius.2`) + label (body-14 medium, `text.secondary`) + value (body-14 regular, `text.primary`) + optional `meta` (body-12 regular, `text.secondary`). Takes a raw `color` string per item (CSS color/token value) rather than a closed status enum — generalized after Security Compliance needed 5 categories that didn't map onto the original 3-value `success`/`warning`/`neutral` set. No gap between rows (removed per user direction — rows sit flush), `spacing.6`/`spacing.12` (vertical/horizontal) padding per row |
| donut chart | `design-systems/xops/components/DonutChart.tsx` | Hand-built SVG (no charting library — declined in favor of full token/color control). Takes `segments: { value: number, color: string }[]` — proportions computed from real `value` numbers, not pre-calculated percentages, so it's live-data-ready. `color` is a raw string (not a status enum) for the same reason as `Legend`. Single ring only (no multi-ring, no center-overlay content, no segment gaps/rounded caps yet — all straightforward to add later without restructuring, deferred until a real need surfaces). Defaults: 164px total size, 24px stroke width, both overridable via props |
| filter tabs | `design-systems/xops/components/FilterTabs.tsx` | Radiogroup of single-select pill buttons — array + controlled `value`/`onChange`, `size` off shared control-height scale. `variant="large"`: stat-tile shape (label + info icon + big value), used by Lifecycle Stage. Selected/disabled states, no icon slot in default variant, no overflow handling, controlled-only. |
