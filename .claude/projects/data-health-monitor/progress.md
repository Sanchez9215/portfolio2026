- **Remediation Request view** (Figma 739:1607, `RemediationRequestPanel.tsx`, opens in-place over Domain Specific — no new route) — reached via "Request Remediation" (unfiltered) or Serial Number's Affected/Single/Multi-Failure values (pre-filtered to that subset); top bar (Cancel/Selected/Projected Healthy CIs/Request stub), 4 summary `Stat` tiles, search + "Show Only Single-Issue CIs" `Toggle` (reused segmented Toggle, not a new binary switch), 8-attribute checkbox accordion (only Serial Number expandable with real entity data — 4 audited rows, "Other Failures" sub-list is page-local synthetic-row markup, not a `Table` capability), other 7 attributes collapsed/inert matching the Validation Failures category pattern. Projected Healthy CIs pill uses `MagicSurface` at `scale={0.3}` (same blob treatment as Software Profile's Opportunity card, no new color tokens)
- **"Configuration Item" terminology → "CI"/"CIs"** — verified against ServiceNow's own CMDB docs (spells out once, then abbreviates); every DHM-facing string (Stat labels, table columns, tooltips, "Duplicate CIs" failure category) now uses CI/CIs, not "Record(s)" or spelled-out "Configuration Item(s)". `PLAN.md`'s one glossary line keeps the spelled-out first mention.
- **`design-systems/xops/data/dataHealth.ts`** — new shared data/logic module: per-domain Completeness/Quality/Recency thresholds (`target`/`warning`, independent per domain), `overallMetric()` (real average of domain values vs. Overall's own independent threshold), `metricState`/`worstState`/`metricLegend` (ranges use `≤`/`≥` + hyphen, matching All Software's `renewalTooltip` convention — no shared boundary number between tiers). Overview's top 3 cards and Overall Status tag now compute from this instead of hardcoded values.
- **`StatusValue` component** (new, `design-systems/xops/components/StatusValue.tsx`) — 8px status dot + plain-text value, `--xops-spacing-6` gap; Health by Domain's Completeness/Quality/Recency cells use it, each with a row-hover-revealed info icon (`Tooltip`, `right-start` placement) showing that domain's own threshold legend — solves per-domain-different-thresholds not fitting a single column-header tooltip. Row-hover reveal via a new inherited CSS var (`--xops-row-hover`, set on `Table.module.css`'s `.row`) so page-local cell content outside `Table`'s own module can key off row hover without needing its hashed class name.
- **`Tooltip`'s default info icon fixed to 16px** — was silently inheriting `Icon`'s 20px default everywhere (including pre-existing Certification header tooltips); now passes `size="16"` explicitly. Unrelated to this session but discovered here: `Icon` itself gained a real `size` prop (16/18/20) — edited directly by the user mid-session.
- **`Table.tsx`'s `width: "flex"` now actually flexes** — previously mapped to `{}` (no width hint), leaving column width to `table-layout:auto`'s content heuristics, which made "flex" columns render inconsistently wide/narrow across different tables. Now gets an explicit equal `%` share of the table (`100 / flexColumnCount`). `showChevron`'s trailing column now participates in that same flex share (counted in `flexColumnCount`) with its existing `data-align="right"` right-aligning the button within it — affects every `Table` consumer in the app, not just DHM.
- **`BarChart` gained a `height="8"` variant** (reusing the existing `--xops-bar-height-8` token ProgressBar introduced) — Single vs. Multi-Failure CIs bar now renders at 8px instead of 16px.
- **Certification Status table's Valid Until + Days Remaining merged into one column** — date + status `Tag` (duration label), mirroring All Software's Renewal column layout, but colored by Certification's own real 4-tier hierarchy (Current/At Risk/Pending Remediation/Overdue — confirmed against the source case-study spec) rather than Renewal's software-urgency thresholds, which don't apply here. `ProgressBar` import dropped (no longer used in this file). Fixed a `validUntil` date-format inconsistency (mixed full/abbreviated months) that was the real cause of visual "stagger," not alignment CSS.
- **Certification's chevron now navigates** — same domain-gated pattern as Health by Domain (only Infrastructure, since it's the only domain with a built detail screen).
- **Sidebar gained a "Control Center" → "Insights" sub-item** routing to `/work/data-health-monitor/prototype` — both DHM screens now pass `activeControlCenterItem="insights"` instead of a placeholder `activeItem="requests"`. Generalized the submenu mechanism into a shared internal `NavGroup` (Control Center and Software both use it now) without changing Software's existing external prop API (`activeSoftwareItem`/`onNavigate`, used by the case-study live-embed).
- **Accessibility finding, not yet acted on**: `Stat`'s `valueDanger`/`valueWarning`/`valueSuccess` (the `-solid` ramp step used as bare text color on the `grey-50` Stat background) fail WCAG AA — danger 3.60:1 (passes 3:1 large-text only), warning 2.06:1, success 2.43:1 (both fail even large-text). Closest passing steps: danger-600 (4.63:1), warning-700 (4.68:1), success-600 (3.60:1, large-text only) or success-700 (5.46:1) if holding every status to the stricter 4.5:1 bar. Previewed live via temporary overrides, then reverted — no token decision made yet.

## Deferred (Roadmap)

- **Tab transition animation** — smooth animation on `FilterTabs` underline-variant tab switch (Insights row: Requests/Employees/Workspace/Worksite/Infrastructure/Software/Data Health). Deferred until the rest of the screen is built.
- **Company-configurable thresholds** — every threshold value (85%, 90%, etc. driving `ThresholdBar`/`Stat` status + delta copy) is currently hardcoded per row. Real data wiring must let each company configure its own thresholds, not ship fixed constants — same category as Software Observability's `config` source table for org taxonomy.
- **4 of 5 failure categories have no audited detail data** — "Validation Failures by Category"'s category list shows real totals for all 5 (Missing Required Data/Business Rule Violation/Format Violations/Duplicate CIs/Referential Integrity), but only Missing Required Data has an audited domain breakdown + bar data. Selecting another category in the list doesn't yet change the detail panel. Needs the other 4 categories' Figma nodes audited before they can go live — applies to both the Overview and Domain Specific views.
- **`ProgressBar`'s `status="info"` needs a cleaner pass** — added quickly for Open Remediation Requests' non-threshold bars; revisit alongside a broader status/variant model.
- **`ProgressBar`'s `.bar` is now capped at `max-width: 152px`** (no `min-width`, since removed this session) — still overshoots Figma's 111px bars in Open Remediation Requests/its nested department table; accepted deviation, not fought.
- **Domain Specific view — only Infrastructure built**; Employee/Worksite/Software domains need their own Figma nodes audited (Health by Domain table rows for them stay inert until then).
- **`#INF-9911`/`#INF-9910` remediation requests have no audited department breakdown** — their nested tables render empty if expanded.
- **`BarChart`'s `.track` background still uses `--xops-border-divider`** — same mistokenization `ProgressBar`'s track had (a border/divider token reused as a surface fill); fixed on `ProgressBar` via the new `--xops-surface-track` semantic token, `BarChart` left alone for now. Swap it to `surface-track` too when touched next — no visual change, just correct tokenization.
- **Overview screen mixes flex `gap` with compensating `marginTop` calc offsets** for one-off spacing between rows in a uniform-gap column (`DataHealthScreen.tsx`) — works but fragile (each offset hardcodes the parent gap it's compensating for) and not the cleanest approach; revisit as a refactor into split sub-groups with their own direct `gap`, no margin math.
- **Remediation Request view's entity data is a 4-row sample, not the full 850** — "Showing X of 850 Records" reflects the real (small) sample size, not Figma's static "200 of 850" mock; no real pagination wired since there's no real dataset yet.
- **Remediation Request view's other 7 attributes have no audited entity data** — same deferred shape as Validation Failures' other 4 categories; checkboxes work, expansion doesn't.
